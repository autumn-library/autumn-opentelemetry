# ОтелДуб

Конфигурационный модуль (дуб) Autumn, регистрирующий желуди OpenTelemetry в контейнере приложения.

## Описание

`ОтелДуб` автоматически подключается при добавлении `#Использовать autumn-opentelemetry` в приложение Autumn. Явно создавать или настраивать его не нужно.

При инициализации регистрирует следующие желуди:

| Жёлудь | Тип | Описание |
|-----|-----|----------|
| `МенеджерПараметров` | `МенеджерПараметров` | Менеджер параметров приложения |
| `ОтелSdk` | `ОтелSdk` | Инициализированный SDK OpenTelemetry |
| `ОтелАппендерLogos` | `ОтелАппендерLogos` | Аппендер для экспорта логов logos через OTel Logs API |
| `ОтелТрассировщик` | `ОтелТрассировщик` | Трассировщик для области `autumn-observed` |
| `ОтелМетр` | `ОтелМетр` | Метр для области `autumn-metrics` |
| `ОтелНаблюдательИсточникаДанных` | `ОтелНаблюдательИсточникаДанных` | Наблюдатель entity с прозвищем `НаблюдательИсточникаДанных`: спаны и метрики источников данных `autumn-data`. При выключенном `otel.entity.enabled` завязь возвращает `Неопределено` |

## Ленивая инициализация

SDK инициализируется лениво — только при первом желуде, требующем инструментирования. Если `otel.enabled = false` или в приложении нет желудей с аннотациями `&Наблюдаемый` / `&Замеряемый` / `&Подсчитываемый`, хранилищ сущностей и менеджеров `autumn-data`, SDK не запускается и экспортёры не стартуют.

## Использование желудей напрямую

Желуди `ОтелТрассировщик` и `ОтелМетр` можно внедрять в свои классы через `&Пластилин`:

```bsl
&Желудь
Процедура ПриСозданииОбъекта(&Пластилин Трассировщик)
    // Трассировщик — экземпляр ОтелТрассировщик
КонецПроцедуры
```

## Конфигурация

Поведение `ОтелДуб` управляется параметрами приложения. Подробнее — в разделе [Конфигурация](/autumn-opentelemetry/configuration.md).
